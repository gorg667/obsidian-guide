    AI in Your Vault¶

    A plain-text vault is the ideal substrate for AI assistance: every note is readable by a model, every file is writable by an agent, and the graph gives context that no chat window has. The risk is the mirror image — an assistant that writes your notes for you produces a vault you do not understand, and a model that reads your journal must be one you trust. This chapter covers what AI is genuinely good for in a knowledge system (and what it ruins), the in-Obsidian plugins, agentic access via the CLI, MCP servers, and agent skills, local models for privacy, voice pipelines, a prompt library, and the privacy rules.

    What AI is good for here — and what it is not¶

    Good Why Bad Why
    Finding: semantic search, "which notes discuss X", surfacing forgotten related notes Models excel at similarity and recall over your own text Writing your idea notes The writing is the thinking; a note you did not write is a note you do not own
    Summarizing sources on capture (Web Clipper Interpreter, long transcripts) as a first pass Saves reading time for triage; you still read what matters Summarizing your journal into "insights" Cheap, generic, and it flattens the texture you kept the journal for
    Extracting structure: properties from text, action items from meeting notes, ingredients from recipes, people mentioned Mechanical, checkable, saves minutes daily Deciding for you Decision notes exist to record your reasoning
    Transforming: transcribe voice, translate, reformat, convert a table, write a Dataview/Bases query from a description Precise tasks with verifiable output Generating filler: "expand this bullet into a paragraph" Produces text nobody wanted to read
    Interrogating: "what did I decide about X and why", "what does my vault say about Y", "contradictions between these notes" RAG over your own words is the killer app Autonomous vault reorganization Bulk edits by an agent are how vaults get destroyed; keep agents on a leash
    Coaching prompts: Socratic questions on a draft, "what would a critic say", weekly-review interviewer Uses the model as a conversation partner, you still write Replacing the review ritual The value of the review is your attention
    Code: Templater scripts, DataviewJS, CSS snippets, Bases YAML, plugin development LLMs are excellent at this and the output is testable

    Principle: AI reads and structures; you write and decide. Let the model touch sources, metadata, transcripts, code, and search. Keep it away from idea notes, decisions, and the journal's content.

    In-Obsidian plugins¶

    Plugin What it does Models Notes
    Copilot (logancyang) Chat sidebar; "vault QA" mode (RAG over your notes with local embeddings); inline commands on selection (summarize, fix grammar, translate, custom prompts); custom prompt templates; context via [[note]] mentions OpenAI, Anthropic, Google, OpenRouter, Ollama/LM Studio (local), Azure The most complete chat-with-vault plugin. Store keys in Keychain where supported.
    Smart Connections "Related notes" pane by embedding similarity (local embeddings by default), plus chat with retrieved context; block-level connections Local embeddings; chat via OpenAI/Anthropic/Ollama and more The best passive AI: a sidebar that always shows semantically related notes — a superpower for finding forgotten notes and duplicate ideas.
    Text Generator Prompt templates that generate into the note; template packs; batch Many For structured generation tasks (extract properties, draft a summary block).
    Local GPT / Ollama plugins Inline completions and commands against a local model Ollama Privacy-first; good for rewriting and extraction.
    Whisper / Voice plugins Record or drop audio → transcript into the note OpenAI Whisper API or local whisper.cpp Voice memos → text.
    Web Clipper Interpreter Prompt variables in clipping templates OpenAI, Anthropic, Gemini, Ollama Chapter 29; pre-distills captures.
    Companion, Copilot Auto-completion Ghost-text completions while typing Various Most people turn these off in a thinking vault — they interrupt.
    Note Toolbar / QuickAdd macros calling APIs DIY: a Templater user script that calls an LLM API Any When you want one specific button ("extract actions from this meeting").

    Setup guidance: install Smart Connections for the related-notes pane (local embeddings; nothing leaves the machine unless you use its chat), and Copilot for chat and inline commands with the provider you trust. Turn off autocompletion. Put API keys in Keychain (1.11+) where the plugin supports it.

    Agentic access from outside: CLI, MCP, skills¶

    The 2026 shift: instead of AI inside Obsidian, coding agents (Claude Code, Codex, Cursor, Gemini CLI, Aider) operate on the vault folder — it is just Markdown — with Obsidian's CLI and file format documentation as their tools.

    Files + CLI¶

    Any agent that can run shell commands can obsidian search, obsidian read, obsidian create, obsidian property:set, obsidian base:query, obsidian tasks, obsidian daily:append — and edit files directly. The CLI's dev:* and eval commands let an agent test a template or plugin it wrote by driving the running app. Point the agent at the vault folder (or a subfolder — keep it out of Journal/ and Mind/), give it the rules below, and it can: fix frontmatter across a folder, convert a Dataview table to a Base, generate a Base from a description, write a Templater template, tag untyped notes after reading them, produce the weekly "vault health" report, build a MOC skeleton from a cluster of notes for you to curate.

    Agent skills¶

    kepano/obsidian-skills (Obsidian's CEO) is a set of Agent Skills — Markdown instruction files following the Agent Skills specification — that teach agents Obsidian's flavour of Markdown, frontmatter/properties conventions, Bases syntax, JSON Canvas, and the Obsidian CLI. Drop them into your agent's skills folder (.claude/skills/ for Claude Code, or the equivalent) and the agent stops inventing invalid Bases YAML or breaking wikilinks. Add your own skill file (vault-conventions.md) describing your schema (Chapter 5), folder tree, and rules ("never edit Journal/ or Mind/", "always set type", "use snake_case").

    MCP servers¶

    Model Context Protocol servers expose the vault to MCP-capable clients (Claude Desktop, Cursor, VS Code, custom agents). Two families: file-based servers (read/write/search over the vault directory — simplest, no Obsidian needed) and REST-API-based servers (talk to the Local REST API plugin, so they see the live app, can run commands, and respect Obsidian's link resolution). Several community servers exist; pick a maintained one, scope it to a subfolder if it supports it, and run it locally. With an MCP server attached, a desktop chat can answer "what did I decide about the kitchen renovation and why?" from your actual decision notes, or "draft a weekly review from this week's daily notes" (as a draft you edit).

    Rules for agents on your vault¶

    # AGENTS.md / vault-conventions skill
- The vault is Markdown; links are [[wikilinks]]; never rewrite them to markdown links.
- Every note has YAML frontmatter with `type`. Do not remove properties you do not understand.
- Never modify anything under Journal/, Mind/, People/ unless explicitly asked for a specific file.
- Prefer creating new notes in Inbox/ over editing existing notes.
- Do not bulk-rename or bulk-move files. Propose a plan first.
- Bases: follow the Bases syntax skill; validate YAML; quote expressions starting with `!`.
- Templater: use <% %> syntax; keep user scripts in Scripts/templater.
- After changes, run: obsidian reload (if needed) and report what changed as a list of paths.
- Commit (Git) before and after any batch change.

    Version control (Git) is what makes agent access safe: every batch change is reviewable and reversible.

    Local models for privacy¶

    If the vault contains journals, health, and finance, sending text to a cloud API is a real decision. Options:

    • Ollama (macOS/Linux/Windows): one command runs Llama, Qwen, Mistral, Gemma, DeepSeek-class models locally; Copilot, Smart Connections, Local GPT, Web Clipper Interpreter, and most MCP setups accept an Ollama endpoint. A modern laptop with 16–32 GB RAM runs 7–14B models fast enough for extraction, summarization, and chat; embeddings are cheap.
    • LM Studio, llama.cpp, Jan: alternatives with GUIs or lower-level control.
    • Local embeddings (Smart Connections default; Copilot option) for semantic search with no data leaving the machine.
    • Local Whisper (whisper.cpp, MacWhisper, faster-whisper) for voice.

    Tiering: local models for anything touching Journal/, Mind/, Health/, Finance/, People/; cloud models (with providers whose data policies you have read, and with training opt-out) for sources, work drafts, code, and public material. Many people simply run everything locally and accept slightly lower quality.

    Voice pipelines¶

    • Quick: system dictation into the daily log (Chapter 27).
    • Memo → transcript → note: record (phone voice memo, Shortcut, or the Whisper plugin's recorder) → Whisper (API or local) → Markdown in Inbox/ with source: voice and the audio embedded or linked → weekly sweep. A Shortcut does this in three actions on iOS; a folder-watcher script (fswatch/watchdog) does it on desktop for a "drop audio here" folder.
    • Meetings: recorder apps with transcripts (or a local whisper on the recording) → the transcript into the meeting note under a collapsed callout; an extraction prompt fills ## Decisions and ## Actions for you to verify. Check consent and legality for recording where you live.
    • Interviews / oral history: long recordings → whisper with speaker diarization (WhisperX) → a Sources/Interviews/ note → quotes extracted into person/family notes (Chapter 23).

    Prompt library¶

    Keep prompts as notes in Meta/Prompts/ (or Copilot's custom prompts) so they are versioned and shareable. Starters:

    Extract structure from a meeting note

    From the notes below, produce: (1) a bullet list of decisions, each one sentence; (2) action items as Markdown tasks - [ ] 👤 Name — action 📅 YYYY-MM-DD when a date is stated, otherwise without a date; (3) open questions. Do not invent items not present in the notes. Keep original wording where possible.

    Properties from a source

    Read the article and return YAML only with: author, published (YYYY-MM-DD or empty), topics (3–6 lowercase nouns), summary (one sentence, ≤ 25 words), claims (3 bullets, each a declarative sentence). No prose.

    Related-notes triage

    Here is a new note and ten candidate related notes (titles + first paragraphs). For each candidate say in ≤ 12 words whether it supports, contradicts, generalizes, is an example of, or is unrelated to the new note. Do not summarize the new note.

    Socratic editor

    I will paste a draft. Do not rewrite it. Ask me the five hardest questions a sceptical, well-informed reader would ask, ordered by how much each would change the piece if I could not answer it.

    Weekly-review interviewer

    Act as a calm interviewer. Ask one question at a time from this list, wait for my answer, follow up once if my answer is vague, then move on: What went well? What did I avoid? Which project has no next action? Who did I not contact that I meant to? What will I stop? Finish by listing my answers as bullets I can paste into my weekly note.

    Dataview/Bases from description

    Write an Obsidian Bases file (YAML) that lists notes with type == "project" and status == "active", columns file.name, area, due, and a formula days_left computing days until due, sorted by due ascending. Follow the Bases syntax exactly; quote any expression beginning with !.

    Contradiction finder

    Here are my idea notes tagged #model. Identify pairs that make incompatible claims. Quote the conflicting sentences. Do not resolve the conflict.

    Journal — permitted use only

    (Local model only.) Below are my daily notes' ## Evening sections for one month. List recurring themes as short phrases with the dates they appear. Do not interpret, advise, or diagnose.

    Workflows that work¶

    1. Capture → structure: Web Clipper Interpreter or a Text Generator template fills properties and a summary; you read the summary and decide keep/delete.
    2. Meeting → actions: after the meeting, one command extracts decisions/actions into the note; you verify and fix owners/dates.
    3. Related-notes sidebar: Smart Connections open while writing idea notes; link what it surfaces (and merge duplicates it reveals).
    4. Ask the vault: Copilot vault-QA or an MCP client for "what do I know about X" before starting a project or a piece of writing; then read the actual notes it cites.
    5. Query and script generation: describe the Base/Dataview/Templater you want; paste; test; keep.
    6. Voice → inbox pipeline for walks and commutes.
    7. Agent maintenance sprints (with Git): "find notes without type in Sources/ and propose types", "convert these five Dataview tables to Bases", "list broken embeds" — review the diff, commit.

    Privacy rules¶

    • Decide per folder what may leave the machine; enforce with local models for the sensitive tiers and, for agents, explicit exclusion rules plus a scoped MCP/agent working directory.
    • Read the provider's data-retention and training policies; use API keys (usually not trained on) rather than consumer chat apps for vault content; opt out where offered.
    • Keys in Keychain or the OS keychain, never in notes or synced data.json without thought (Chapter 26).
    • Agents get Git and a leash: no bulk operations without a plan, commit before and after.
    • Do not paste other people's private information into cloud models (People notes, meeting notes with sensitive content).
    • Keep the output labelled: notes or sections written by a model get source: ai or a > [!ai] callout so future you knows what to trust.

    Anti-patterns¶

    • Letting the model write idea notes and decision reasoning.
    • Autocompletion in a thinking vault.
    • Uploading the whole vault to a chat app "to ask questions".
    • Agents with write access to Journal/, Mind/, People/.
    • Bulk AI tagging that produces 400 tags.
    • Summaries of summaries: the model summarizes the article, then your note, then your review — nothing is read.

    Key takeaways¶

    • AI reads and structures; you write and decide. Use it for finding, summarizing sources, extracting structure, transforming, interrogating your own words, and code — not for idea notes, decisions, or the journal.
    • Smart Connections (related notes, local embeddings) and Copilot (chat, vault QA, inline commands) are the in-app pair; keys in Keychain; autocompletion off.
    • Coding agents operate on the vault folder with the Obsidian CLI and Agent Skills (kepano/obsidian-skills + your own conventions); MCP servers connect desktop chats to the vault; Git makes it safe.
    • Local models (Ollama) for sensitive folders; cloud models for sources, drafts, and code; voice via Whisper pipelines.
    • Keep a prompt library in the vault; label AI output; give agents rules and a leash.
